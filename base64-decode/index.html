Base64 Decode

Paste a Base64 string and get the text back. URL-safe input and missing padding are handled for you, and the decoding happens in your browser.

Type or paste text, then choose Encode or Decode.

Try next Base64 Encode & Decode JSON Formatter & Beautifier JSON Validator

How to decode Base64

  1. Paste the Base64 string into the Input box. Spaces and line breaks are ignored.
  2. Press Decode (or Ctrl/Cmd + Enter).
  3. Press Copy to take the text. If it is JSON, use Use output as input and then open the JSON formatter.

Examples

SGVsbG8sIHdvcmxk   →   Hello, world

A JWT header is a typical thing to decode. It uses the URL-safe alphabet with no padding, and this tool accepts it as it is:

eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9   →   {"alg":"HS256","typ":"JWT"}

A JWT is three Base64URL segments separated by dots (RFC 7519). The first two are JSON, so paste one segment at a time and then check it with the JSON validator. The third is the signature, which is not text.

What the tool does when you press Decode

  1. Removes spaces, tabs and line breaks from both ends and from inside the text.
  2. Turns - into + and _ into /, so URL-safe input becomes standard Base64.
  3. Adds = until the length is a multiple of 4.
  4. Decodes the result to bytes with the browser's own Base64 decoder.
  5. Reads the bytes as UTF-8. Bytes that are not valid UTF-8 are rejected, not replaced with question marks.

RFC 4648 says a decoder must reject characters outside the alphabet unless the specification it serves says otherwise, and notes that MIME-style data may have its line breaks ignored. This tool follows the second case for whitespace only.

The two error messages

  • Not valid Base64. The text has a character outside A-Z, a-z, 0-9, + and / (or - and _), misplaced or surplus =, or a length that cannot be right. Compare it with the table above.
  • Valid Base64, but the bytes are not UTF-8 text. The decoding worked, but the result is binary data or text in another encoding. See the next section.

When the result is not text

Base64 is a way to carry bytes, not a type of data. If the original was an image, a PDF or an archive, the decoded bytes are not readable text and this tool will report an error instead of showing nonsense. Save such data to a file with a tool built for binary content. Encrypted data and hashes also decode to random bytes.

Base64 is also not encryption. If decoding reveals a password or a key, treat it as exposed. The guide to Base64 explains why.

Decode Base64 in code

JavaScript, in a browser or Node. This does what the tool does. atob throws an InvalidCharacterError for text that is not Base64, and the strict decoder throws a TypeError for bytes that are not UTF-8:

function decode(input) {
  let s = input.trim().replace(/\s+/g, "").replace(/-/g, "+").replace(/_/g, "/");
  while (s.length % 4) s += "=";
  const bin = atob(s);
  const bytes = Uint8Array.from(bin, (c) => c.charCodeAt(0));
  return new TextDecoder("utf-8", { fatal: true }).decode(bytes);
}

console.log(decode("8J-YgA")); // 😀

In Node, Buffer is shorter but lenient. It accepts both alphabets and ignores whitespace, and it does not throw on bad input. For !!!! it returned an empty string, so check the result:

Buffer.from("8J-YgA", "base64").toString("utf8"); // 😀

Python. validate=True makes b64decode reject characters outside the alphabet instead of skipping them. The padding line adds back any = that was dropped:

import base64

def decode_any(s):
    """Accepts standard or URL-safe input, with or without padding."""
    s = "".join(s.split()).replace("-", "+").replace("_", "/")
    s += "=" * (-len(s) % 4)
    return base64.b64decode(s, validate=True).decode("utf-8")

print(decode_any("8J-YgA"))  # 😀

Python raises binascii.Error for bad Base64 (for example Incorrect padding or Non-base64 digit found, worded by version) and UnicodeDecodeError for bytes that are not UTF-8.

Command line. GNU base64 wants the padding. Given SGk it prints Hi, then reports base64: invalid input and exits with status 1:

printf '%s' 'SGVsbG8sIHdvcmxk' | base64 --decode

PowerShell:

[Text.Encoding]::UTF8.GetString([Convert]::FromBase64String("SGVsbG8sIHdvcmxk"))

PowerShell's error for the unpadded SGk is Invalid length for a Base-64 char array or string.

Limits of this tool

  • It decodes to text only. Images, PDFs and other binary data are reported as an error.
  • It reads UTF-8. Text that was encoded in Latin-1 or UTF-16 does not decode here.
  • It reads pasted text. There is no file upload.
  • Everything runs in your browser. The tool's code does not send what you paste anywhere; see the privacy policy for the analytics the site does run.

To go the other way, use Base64 encode, which also explains the alphabet, padding and size increase.

Frequently asked questions

Does it accept URL-safe Base64?

Yes. - and _ are treated as + and /, and missing = padding is added back, so strings taken from a URL or a JWT decode without edits. Standard and URL-safe characters can even be mixed in one string.

Can I decode a JWT here?

You can decode the header and payload, which are Base64URL-encoded JSON: paste one segment (the text between the dots) at a time. Decoding does not verify the signature, so never trust a token because it decodes.

Why do I see an error instead of text?

If the message says the text is not valid Base64, it contains something outside the alphabet or has the wrong length. If it says the Base64 is valid but the bytes are not UTF-8 text, the data is probably an image, a PDF or compressed data. This tool decodes text only.

Why does decoding fail with an invalid string?

Check for characters outside A-Z, a-z, 0-9, + and / (or - and _), stray quotes, too many = signs, = in the middle, or a string cut off in the middle. Line breaks and spaces are ignored.

How do I decode a data URL such as data:text/plain;base64,...?

Paste only the part after the comma. The prefix, data:text/plain;base64, is not Base64, so including it causes an error. If the media type is an image, the decoded bytes are not text and this tool cannot show them.

How do I decode Base64 on the command line?

With GNU coreutils, printf '%s' 'SGVsbG8sIHdvcmxk' | base64 --decode. In PowerShell, [Text.Encoding]::UTF8.GetString([Convert]::FromBase64String("SGVsbG8sIHdvcmxk")). Both want the = padding to be present.

Why is the decoded text garbled?

The bytes are probably text in another encoding, or not text at all. This tool reads the decoded bytes as UTF-8 and refuses anything that is not valid UTF-8, so garbled output usually shows up as an error. Text that was encoded as Latin-1 or UTF-16 will not decode here.

Is Base64 reversible without a key?

Yes, and that is why it is not encryption. Anyone can decode it. If decoding reveals a password or a key, treat it as exposed.

Is my input uploaded?

No. Decoding happens in your browser, and the page's code makes no network request with your text. The site does run page-level analytics, described in the privacy policy, but that does not include what you paste.
