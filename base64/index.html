What Base64 is

Base64 writes any bytes using only 64 safe text characters: the letters A to Z and a to z, the digits 0 to 9, and + and /. That lets binary data travel through places that only accept text, such as email, JSON or a URL. It is an encoding, not encryption, and not compression: it makes data larger, and anyone can reverse it.

How to use it

  1. Type or paste text into the Input box.
  2. Press Encode to get Base64, or paste Base64 and press Decode to get the text back.
  3. Tick URL-safe output before encoding if the result goes in a URL, a filename or a JWT.

Want the background? Read what Base64 is and when to use it. To only decode, use the Base64 decode page.

Example

Hello, world   →   SGVsbG8sIHdvcmxk

Standard Base64 can contain +, / and trailing =. The URL-safe form replaces the first two with - and _ and drops the padding. For the text ??>> the two forms are:

standard   Pz8+Pg==
URL-safe   Pz8-Pg

How the encoding works

Base64 takes the input 3 bytes (24 bits) at a time and splits those 24 bits into four groups of 6 bits. Each 6-bit value, from 0 to 63, is written as one character from the alphabet. When the input is not a multiple of 3 bytes, the last group is padded with = signs:

InputBytesBase64Padding
Man3TWFunone
Ma2TWE=one =
M1TQ==two =

RFC 4648 notes that the = in a URI is normally percent-encoded, so URL-safe Base64 usually skips the padding when the data length is known another way. The tool's URL-safe option drops it.

How much bigger is Base64?

Every 3 bytes become 4 characters, so the output length is 4 times the input length divided by 3, rounded up. 1,000 bytes become 1,336 characters, about a third more. The tool shows the size of the input and the output above each box.

Unicode text and UTF-8

Base64 encodes bytes, not letters, so text has to become bytes first. This tool uses UTF-8, the usual choice on the web. A plain letter is 1 byte, é is 2 bytes and an emoji such as 😀 is 4:

TextUTF-8 bytesBase64
é2w6k=
😀48J+YgA==

If another tool encodes the same text as UTF-16 or Latin-1, its Base64 will differ from this one for anything that is not plain ASCII.

Encode Base64 in code

JavaScript, in a browser or Node. btoa only accepts characters up to code 255 and throws an InvalidCharacterError on anything else, so convert text to UTF-8 bytes first:

const text = "héllo 😀";
const bytes = new TextEncoder().encode(text);
const b64 = btoa(Array.from(bytes, (b) => String.fromCharCode(b)).join(""));
console.log(b64); // aMOpbGxvIPCfmIA=

// URL-safe: swap two characters and drop the padding
console.log(b64.replace(/\+/g, "-").replace(/\//g, "_").replace(/=+$/, ""));

In Node, Buffer does the same in one call and has a URL-safe name:

Buffer.from("héllo 😀", "utf8").toString("base64");    // aMOpbGxvIPCfmIA=
Buffer.from("??>>", "utf8").toString("base64url");     // Pz8-Pg

Python. urlsafe_b64encode keeps the = padding, so strip it if you want the unpadded form:

import base64

print(base64.b64encode("héllo 😀".encode("utf-8")).decode("ascii"))
print(base64.urlsafe_b64encode("??>>".encode("utf-8")).decode("ascii").rstrip("="))

Command line. Use printf, not echo, so no line break is encoded. GNU base64 wraps its output every 76 characters; -w 0 turns that off:

printf '%s' 'Hello, world' | base64
printf '%s' 'Hello, world' | base64 -w 0

PowerShell:

[Convert]::ToBase64String([Text.Encoding]::UTF8.GetBytes("Hello, world"))

Common mistakes

  • Encoding a trailing newline. echo Hello | base64 gives SGVsbG8K, not SGVsbG8=.
  • Calling btoa on Unicode. It throws, or if the characters happen to fit in one byte, it encodes Latin-1 rather than UTF-8: btoa("héllo") gives aOlsbG8=, while the UTF-8 form is aMOpbGxv.
  • Using standard Base64 in a URL. Use the URL-safe form, or percent-encode the +, / and =.
  • Treating it as secret. Base64 hides nothing. See the Base64 guide.

Limits of this tool

  • It encodes and decodes text only. There is no file or image input.
  • Decoding needs the result to be valid UTF-8 text; binary results are reported as an error, not shown.
  • Everything runs in your browser. The tool's code does not send what you paste anywhere; see the privacy policy for the analytics the site does run.

Base64 often carries JSON. After decoding, check it with the JSON validator or tidy it with the JSON formatter.

Frequently asked questions

Is Base64 encryption?

No. Base64 is an encoding that anyone can reverse without a key. Never use it to hide passwords or secrets.

Why is the output longer than the input?

Base64 turns every 3 bytes into 4 characters, so the output is about 33% larger than the input, plus padding. The exact length is 4 times the input length in bytes divided by 3, rounded up. 1,000 bytes become 1,336 characters.

What is URL-safe Base64?

A variant that uses - and _ instead of + and /, and usually drops the = padding, so the result can sit inside a URL or filename. It is defined in RFC 4648, section 5.

What does the = at the end mean?

It is padding. Base64 works in groups of 3 bytes. If the last group has only 1 byte the output ends in ==, and if it has 2 bytes the output ends in a single =. A multiple of 3 bytes needs none.

Does it handle emoji and accented text?

Yes. Text is converted to UTF-8 bytes before encoding, so any Unicode character round-trips correctly. Functions that assume one byte per character, like a bare btoa, fail on such text.

Why does my command line give a different result from this tool?

Usually because echo adds a line break to the text, and the break is encoded too: echo Hello | base64 gives SGVsbG8K, while printf with the text and no newline gives SGVsbG8=. GNU base64 also wraps its output at 76 characters unless you pass -w 0.

How do I encode a file or an image?

This tool encodes text only. For a file, use a command-line tool: base64 file.png with GNU coreutils (Linux, Git Bash), or [Convert]::ToBase64String([IO.File]::ReadAllBytes("file.png")) in PowerShell. Your code can do the same with the byte-level functions shown on this page.

Is what I type uploaded anywhere?

No. Encoding runs in your browser, and the page's code makes no network request with your text. The site does run page-level analytics, described in the privacy policy, but that does not include what you paste.

Why does decoding fail?

Either the text is not valid Base64, or it decodes to bytes that are not UTF-8 text, such as an image or a compressed file. This tool decodes text only. The Base64 decode page lists what is accepted and what is rejected.
