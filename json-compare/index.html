How to compare two JSON documents

  1. Paste the original into the left box and the changed version into the right box. Press Sample to see an example.
  2. Press Compare. If either side is invalid JSON, the error tells you which side and where.
  3. Read the list: added values exist only on the right, removed only on the left, and changed shows the old and new value.

Why a structural diff beats a text diff

A normal text diff reports a change whenever two lines differ, including when a service returns the same object with its keys in a different order, or when one file is minified and the other pretty-printed. Comparing the parsed structure ignores those differences and shows only changes in the data.

Typical uses

  • Checking that an API response did not change after a deploy.
  • Finding what differs between two environments' config files.
  • Reviewing a fixture or snapshot update in a test.

Tip: format both documents first if you also want to read them side by side.

Frequently asked questions

Does key order matter?

No. Two objects with the same keys and values are identical here, however the keys are ordered. This is a structural comparison, not a text diff.

How are arrays compared?

By position. Element 0 is compared with element 0, and so on. If an item is inserted at the start of an array, every later index will show as changed. That is a known limit of index-based comparison.

What does the path mean?

It locates the value, starting from $ (the root). $.user.roles[1] is the second item of the roles array inside user.

Is my data uploaded?

No. Both documents are parsed and compared in your browser. Nothing is sent anywhere.

Is there a limit on differences?

The list shows the first 500. If you reach it, the two documents are very different and a text diff in your editor may be more useful.
