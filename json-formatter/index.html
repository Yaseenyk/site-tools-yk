What a JSON formatter does

A JSON formatter, also called a beautifier or pretty printer, rewrites JSON with line breaks and indentation so you can see its structure. JSON does not care about spaces between its tokens, so formatted and unformatted JSON describe the same data. The opposite job, removing the whitespace, is done by the JSON minifier.

How to format JSON

  1. Paste your JSON into the Input box, or press Sample to try it.
  2. Press Format (or Ctrl/Cmd + Enter). Choose 2 spaces, 4 spaces or tabs first if you have a house style.
  3. Tick Sort keys if you want stable alphabetical order, then press Copy.

If the input is invalid, the status bar shows the parser's message with the line and column. The guide to the six most common JSON errors covers each fix, and the JSON validator lists the messages and their causes.

Before and after

{"user":{"id":1042,"roles":["admin","editor"]},"active":true}

becomes

{
  "user": {
    "id": 1042,
    "roles": [
      "admin",
      "editor"
    ]
  },
  "active": true
}

With Sort keys ticked, the same input starts with "active" and then "user", because the keys are put in alphabetical order at every depth.

What else the formatter changes

The tool reads your text into a JavaScript value and writes it back out. For almost all JSON that gives the same data with new whitespace. A few inputs come back different, because a JavaScript value cannot hold everything the JSON text can:

In your textIn the outputWhy
1.0, 1e2, 0.101, 100, 0.1Numbers are written in their shortest form. The value is the same.
-00The sign of zero is not written.
1234567890123456789012345678901234567000The number is held as a 64-bit float and loses digits above 2^53.
1E400nullToo large for a 64-bit float, so it becomes infinity, which is written as null.
"é", "\/""é", "/"Escapes that are not required are written as the plain character.
{"b":1,"2":2,"1":4}{"1":4,"2":2,"b":1}JavaScript puts whole-number keys first, in ascending order.
{"a":1,"a":2}{"a":2}A repeated key keeps only its last value.

If an exact digit string or the exact key order matters, do not round-trip the document through any JavaScript-based formatter. Keep long IDs as strings in the source.

Format JSON in code

JavaScript, in a browser or Node:

const text = '{"user":{"id":1042,"roles":["admin","editor"]},"active":true}';
console.log(JSON.stringify(JSON.parse(text), null, 2));

The third argument is the indent: a number of spaces, or a string such as a tab. Python, from the standard library:

import json

text = '{"user":{"id":1042,"roles":["admin","editor"]},"active":true}'
print(json.dumps(json.loads(text), indent=2, ensure_ascii=False))

ensure_ascii=False keeps accented letters and emoji as they are instead of writing \uXXXX escapes. Add sort_keys=True to sort the keys. Python keeps whole-number keys in their original order, unlike JavaScript, and reads large integers exactly.

On the command line, Python ships a formatter. It indents with 4 spaces unless you say otherwise:

python -m json.tool in.json
python -m json.tool --indent 2 --sort-keys in.json
cat in.json | python -m json.tool

To use Node instead, read standard input:

node -e 'console.log(JSON.stringify(JSON.parse(require("fs").readFileSync(0, "utf8")), null, 2))' < in.json

Limits of this tool

  • It reads standard JSON only. Comments, trailing commas, single quotes and unquoted keys are errors, not something it repairs.
  • It formats one JSON document. A file with one JSON value per line (JSON Lines) fails with Unexpected non-whitespace character after JSON; format each line on its own.
  • You paste text. There is no file upload and no size cap, but a very large paste is slow.
  • Everything runs in your browser. The tool's code does not send what you paste anywhere; see the privacy policy for the analytics the site does run.

What counts as valid JSON

JSON is stricter than a JavaScript object literal. Keys and strings use double quotes, there are no trailing commas and no comments, and the only values are objects, arrays, strings, numbers, true, false and null. The format is defined in RFC 8259. The full list of rules, with the error message for each, is on the JSON validator page. To browse a large document without reading it all, use the JSON viewer.

Frequently asked questions

How do I pretty print JSON?

Paste it into the Input box and press Format. The JSON is re-indented with 2 spaces, 4 spaces or tabs, with each key and array item on its own line. Pretty printing changes the layout, not the structure. A few values are rewritten as a side effect; the section on what else the formatter changes lists them.

Is my JSON uploaded anywhere?

No. Parsing and formatting run in your browser with JavaScript's built-in JSON parser, and the page's code makes no network request with your text. The site does run page-level analytics, described in the privacy policy, but that does not include what you paste.

What is the difference between formatting and validating?

Validating only tells you whether the text is legal JSON. Formatting also rewrites it with consistent indentation so a person can read it. Formatting only works on valid JSON, so a format that fails is also a validation failure.

What does Sort keys do?

It rewrites every object with its keys in alphabetical order, at every depth. Arrays keep their order. Sorted output makes two documents much easier to compare line by line.

Why did the order of my keys change?

JavaScript lists keys that look like whole numbers (such as "1" or "42") first, in ascending order, and the other keys after them in their original order. Because the tool formats through a JavaScript object, {"b":1,"2":2,"1":4} comes out as {"1":4,"2":2,"b":1}. Key order carries no meaning in JSON, but it can matter to a text diff.

Why does formatting change my big numbers?

JavaScript reads JSON numbers as 64-bit floats, so integers larger than 9,007,199,254,740,991 can lose precision: 12345678901234567890 is written back as 12345678901234567000. RFC 8259 says integers in the range of plus or minus (2^53 minus 1) are the ones every implementation will agree on. If you handle IDs that large, keep them as strings.

Why does the formatter say my JSON is invalid when it works in my code?

Most likely it is a JavaScript object literal, not JSON. Object literals can have unquoted keys, single quotes, trailing commas, comments and values like undefined. JSON allows none of these. The error message shows the line and column of the first problem.

Can I format JSON with comments or trailing commas?

No. Comments and trailing commas are not part of JSON, so the tool reports an error and does not guess. Remove them first. Formats such as JSONC and JSON5 allow them, but this tool reads standard JSON only.

Is there a size limit?

This page sets none. Documents of tens of megabytes may be slow because everything runs in your browser's memory.
